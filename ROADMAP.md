## 3. Update protocol (every contribution)

Do all of these **in the same commit as the work**:

1. **Status:** set the checkbox of every item you touched (legend in §4). Add the date and your name/agent id on `[~]`.
2. **Evidence:** for `[x]`, add one line `Evidence:` naming the test, command output, file, or SPIKE_RESULTS entry that proves it. No evidence → not done.
3. **New work found:** add a new item with the next free ID in its phase. **Never reuse or renumber IDs.**
4. **Cut work:** mark `[-]` with a reason. Do not delete items.
5. **Update log:** append an entry at the **top** of §10: `date (UTC) · who · item IDs · summary · files/areas · evidence · follow-ups`. Trivial changes (typos, docs-only) still get a one-line entry.
6. **Dashboard:** refresh the progress table (`npm run roadmap:check -- --write` once F-11 exists; by hand before that).
7. **Current focus (§2):** update to the next 3–5 items.
8. **Blockers (§8):** add or clear entries.
9. **Facts:** if you resolved a `[Unverified]` claim, record it in `docs/SPIKE_RESULTS.md`, update the affected doc's marker, and list the doc in the log entry.
10. **Merge conflicts in this file:** keep both sides' log entries, sort by timestamp, newest first; recount the dashboard.

Never rewrite or delete past log entries. Never mark something done that was not run.

Closed paths: `NEAR_PATHS` asserted as exactly the four SPIKE endpoints and `/v1/models` asserted absent. URL steering refused at construction: relay base must be same-origin under `/api/relay/v1` (an absolute `https://evil.example/api/relay/v1`, a `..`-containing path and a wrong prefix each throw), direct mode is pinned to `cloud-api.near.ai` over https and needs a header provider (ADR-17), and **fixture mode refuses to build a network client** — it throws `NotBuilt('F-09')` rather than falling through to `fetch`, because a "demo data" run that spends someone's credits is both a privacy lie and a bill. ADR-19 is served by the return shape: `post` hands back `sentBody` (byte-identical to what the double received, asserted) and `rawText` **un-trimmed** — a streaming body ending in two newlines is preserved — and there is no second `.json()` anywhere in the file, so what gets hashed is what arrived. Retry is **one** and status-aware: transport failure retried once then `network_lost` (2 calls, not a loop); 429/5xx retried once; a GET 404 retried once because the signature cache is per-node, a POST 404 **not** retried because the model is genuinely absent; a 200 with an unparseable body is never retried (the completion was already charged and a second returns different bytes). Abort is its own outcome, not a network failure: pre-aborted sends nothing, and a cancel during the retry wait reports `aborted`. Rule 7 tested with a sentinel — document text in the request and service text in the response appear in neither the error message, the `AppError`, nor a serialisation of the error, which carries only path + HTTP status. One code path proven for three modes: relay sends no `authorization`, direct asks the provider **per call** so a key pasted in Settings takes effect without rebuilding.
